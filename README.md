# AIO 구매 도우미 (크롬 익스텐션)

node 판 기능 셋을 크롬 안으로 옮긴 것입니다.

| 기능 | 원본 | 하는 일 |
|---|---|---|
| 클릭 흐름 | `pg_clicks` · `pg_finish` · 주문서 `payHere` | 주소가 맞는 화면에서 정해 둔 글자의 버튼을 차례로 누른다 |
| 간편결제 비밀번호 | `node/src/naver/pin.ts` · `node/src/lotte-test/browser.ts` | 네이버페이·L.PAY 자판을 읽어 누른다 |
| 디스코드 알림 | `node/src/discord-open/` | 우리 웹훅 알림 속 링크를 새 창으로 연다 |

**처음에는 전부 꺼져 있습니다.** 팝업의 큰 스위치와 기능별 체크를 켜야 움직입니다.

## 사이트별 버튼 (팝업에 이 순서로 묶여 있습니다)

| 사이트 | 버튼 | 주소 조각 | 누르는 것 |
|---|---|---|---|
| **네이버** | 상품 페이지 → 구매하기 (옵션 없는 상품만) | `brand.naver.com` · `smartstore.naver.com` 의 `/products/번호` | `구매하기` → 레이어가 뜨면 그 안의 `바로구매` |
| | 주문서 → 결제하기 | `orders.pay.naver.com` | `결제하기` (금액 롤러가 든 `button-pay` 버튼) |
| | 네이버페이 마지막 확인 | `://pay.naver.com` | `결제내용에 동의` → `결제` |
| | 네이버페이 비밀번호 자동 입력 | `pay.naver.com/authentication` | 스프라이트 자판을 읽어 6자리 |
| **롯데온** | 상품 페이지 → 바로 구매하기 | `lotteon.com/p/product/` · `/m/product/` | `바로 구매하기` (없으면 `바로구매`) |

| | L.PAY 비밀번호 자동 입력 | `lotteon.com` (자판이 보일 때만) | 글자 자판 6자리 → 남아 있으면 확인 키 |

| **디스코드** | 알림 링크를 새 창으로 열기 | — | 웹훅 알림 속 링크 |

비밀번호는 결제수단마다 따로 저장합니다 (네이버페이 것과 L.PAY 것이 다르니까).

## 설치

1. 크롬 주소창에 `chrome://extensions`
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 `extension` 폴더 선택
4. 툴바의 퍼즐 조각 → **AIO 구매 도우미** 고정

코드를 고친 뒤에는 `chrome://extensions` 에서 새로고침(↻)을 누르고, 열려 있던 쇼핑 탭도 새로고침하세요.

## 처음 켤 때 권하는 순서

1. 팝업에서 **연습 모드** 를 켠 채로 큰 스위치를 켠다
2. 주문서·결제창을 한 번 지나가 본다. 누를 버튼에 **빨간 테두리**만 생기고 누르지는 않는다.
   비밀번호 자판은 누를 숫자를 차례로 빨갛게 짚어 준다
3. 팝업 아래 **기록** 에서 무엇을 눌렀을지 확인한다
4. 맞으면 연습 모드를 끈다

## 간편결제 비밀번호

- 팝업의 사이트 칸(네이버 / 롯데온)에서 숫자 6자리를 넣고 **저장**합니다.
- 기본은 **브라우저를 끄면 지워집니다** (`chrome.storage.session`, 메모리에만 있음).
  "브라우저를 꺼도 기억" 을 켜면 크롬 프로필 폴더에 **평문으로** 남습니다. 이 PC를 같이 쓰는
  사람이 있으면 켜지 마세요.
- 비밀번호를 넣는 순간 결제가 끝나는 계정이 많습니다. 주문서 흐름과 같이 켜면 **사람 손 없이 삽니다.**
- 틀렸다는 말이 뜨면 **다시 넣지 않습니다.** 몇 번 틀리면 결제가 잠기기 때문입니다.
- 매 자리마다 자판을 다시 읽고, 점 개수가 늘었는지로 눌렸는지 확인합니다.
- 한 페이지에서 결제수단마다 **한 번만** 넣습니다. 다시 넣게 하려면 페이지를 새로고침하세요.
- **L.PAY** 자판은 주문서 위에 뜨는 레이어이고 숫자가 글자로 들어 있습니다 (2026-08-25 에 받아 적은
  `lotteon-test-keypad-html.txt`). 점은 `.apiPassword span.on`, 여섯 자리 뒤에 자판이 남아 있으면 확인 키를 누릅니다.
  "5회 잘못" 이 떠 있으면 시작하지 않습니다.
- 자판이 자바스크립트 클릭을 무시하면 `chrome.debugger` 로 진짜 클릭을 냅니다. 그동안 크롬 위에
  "디버깅을 시작했습니다" 띠가 잠깐 뜹니다. 인증 화면이 **iframe 안** 에 있으면 이 방법은 안 되고, 멈춰서 사람에게 넘깁니다.

0.2.6 (2026-09-19, "네이버도 결제 전까지 클릭 딜레이 최대한 없애줘"):

- **화면이 바뀌는 순간 봅니다.** 0.2초마다 보던 것에 더해 DOM 이 바뀌면 곧바로 한 바퀴 돕니다 (MutationObserver).
  네이버 주문서 결제 버튼은 금액 숫자가 도는 애니메이션이라 화면이 쉬지 않고 바뀌어서, 바퀴는 최소 30ms 간격으로 모읍니다.
- 네이버 흐름 단계 사이 쉼: 마지막 확인(`결제내용에 동의` → `결제`) 0.7초 → 0.1초. 주문서 결제하기 0.
- 네이버페이 자판: 뜨고 0.5초 → 0.15초 뒤 시작, 자리 사이 0.12초 → 0.04초. 안 먹으면 자리마다 다시 누르는 것은 그대로.
  L.PAY 는 잘 되는 그대로 둡니다.
- 백그라운드가 설정을 메모리에 들고 있습니다 (바퀴마다 저장소를 읽지 않게). 이 페이지에서 끝낸 흐름은 다시 묻지 않습니다.
- 네이버페이 자판 그림을 `decode()` 대신 `onload` 로 읽습니다 — `decode()` 는 창이 가려져 있으면 끝나지 않아 자판을 영영
  못 읽었습니다. 자판이 아직 안 보이면 "못 읽었다" 가 아니라 "아직 안 떴다" 로 칩니다.
- 모의 페이지에서 잰 것: 주문서 결제 버튼은 뜨고 **1ms** 만에 한 번 눌림. 네이버페이 6자리(누를 때마다 섞이는 자판)는
  자판이 보이고 **약 0.5초** 에 다 들어감.

0.3.0 (2026-09-19, "네이버도 진짜 클릭처럼" · "옵션 있으면 구매하기 누르지 말고"):

- **네이버도 진짜 클릭입니다.** 주문서 결제하기·마지막 확인·상품 페이지 구매하기(흐름의 `trusted: true`), 네이버페이 비밀번호.
  그 페이지가 열리자마자 진짜 클릭을 켜 둡니다 — "디버깅 중" 띠로 페이지가 밀리는 것이 누르기 전에 끝나게.
- **네이버페이 비밀번호도 L.PAY 와 같은 길**(lotte-test `enterPin` 순서)로 넣습니다. 다른 것은 쉬는 시간뿐
  (`PIN_TIMING`: 네이버페이는 짧게, L.PAY 는 잘 되는 그대로). 옛 네이버페이 입력 코드는 지웠습니다.
- **새 흐름: 네이버 상품 페이지 → 구매하기 (옵션 없는 상품만)** — 기본 꺼짐. 옵션 판단은 페이지 속 상품 상태
  (`__PRELOADED_STATE__` 의 `optionUsable`·`optionCombinations`, 주소의 상품 번호로 찾음)가 먼저고, 못 읽으면 화면의
  옵션 선택 칸("선택하세요" 등)을 봅니다. **옵션이 있으면 누르지 않고 기록에 남깁니다.** 둘 다 모르면 누릅니다 —
  옵션 상품에 잘못 눌러도 네이버가 "옵션을 선택해 주세요" 로 막을 뿐입니다. 구매하기 뒤 구매 레이어가 뜨면 그 안의
  `바로구매` 를 한 번 더 누르고(node 판 `throughLayer`), 1.5초 지나도 아무 일이 없으면 4번까지 다시 누릅니다.
  옵션 상품 페이지에서는 진짜 클릭을 미리 켜지 않습니다.
- 기록이 빠지던 것을 고쳤습니다 — 거의 동시에 온 기록 둘 중 하나가 다른 것을 덮어썼습니다.

## 클릭 흐름

설정 화면(팝업 아래 "설정 자세히")에서 JSON 으로 고칩니다. 기본 흐름은 위 표에 있습니다.
각 흐름의 `site` 가 팝업에서 어느 칸에 묶일지를 정합니다.

**롯데온 바로 구매하기** 를 켜 두면 롯데온 상품 페이지를 여는 것만으로 누릅니다. 버튼이 없으면(품절)
기다리다가 생기는 순간 누릅니다 — 디스코드 알림으로 열린 페이지에서 바로 구매로 이어지게 하려는 것입니다.
그냥 구경하러 들어갈 때는 꺼 두세요.

0.2.1 에서 고친 것 (2026-09-19, "롯데온 잘 안 눌려"):

- **페이지가 다 뜨고 버튼이 0.8초 그대로 있을 때 누릅니다** (`readyMs`). 실제 페이지에서 확인해 보니 버튼은
  Vue 로 그려지고 클릭은 가짜 클릭도 받습니다(`buttonClick → buttonAction → addCartBuyNow`). 뜨자마자 누르면
  상품 데이터가 덜 불러와져 조용히 무시될 수 있어서 기다립니다.
- **눌렀는데 넘어가지 않으면 다시 누릅니다** (`retry`, 2.5초 뒤 · 3번까지). 예전에는 한 번 누르면 30초 동안
  끝난 것으로 쳐서, 첫 클릭이 안 먹으면 그대로 멈췄습니다. 3번 다 안 되면 기록에 빨간 글씨로 남깁니다
  (옵션 선택·로그인·알림창을 보세요).
- **못 찾으면 이유를 남깁니다.** 예: `'바로 구매하기' 버튼이 안 보입니다 — 보이는 버튼: 일시품절된 상품입니다`.
- **품절이면 새로고침** — 팝업의 "품절이면 N초마다 새로고침" (기본 0 = 안 함). 롯데온 상품 페이지는 재입고돼도
  스스로 바뀌지 않아서, 품절 페이지를 열어 두고 기다리려면 켜야 합니다. 너무 짧게 잡으면 사이트에 부담이니 5초 이상으로.
- 화면 밖에 숨은 건너뛰기 링크 `<a href="#toGoPurchase">구매하기</a>` 가 있어서 `구매하기` 는 후보에 넣지 않습니다.

0.2.2 에서 고친 것 (2026-09-19, "잘 되긴 하는데 바로바로 안 눌려"):

- **새로 연 상품 페이지에서는 쉬지 않습니다** (`cooldownScope: "page"`). 예전엔 한 번 누르면 30초 동안 다른 상품
  페이지에서도 안 눌렀습니다 — 기록의 20:12:30 → 20:13:01 이 딱 그 30초였습니다. 이제 쉬는 것은 누른 그 페이지뿐입니다.
  결제 버튼 흐름(주문서 → 결제하기)은 그대로 어느 페이지든 60초 쉽니다. 결제가 실패해 주문서가 새로 떠도
  결제하기·비밀번호를 되풀이하지 않게 하려는 것입니다.
- **페이지 로딩 완료를 기다리지 않습니다.** 재 보니 버튼은 0.9초에 뜨는데 로딩 완료는 2.8초였습니다. 이제 버튼이
  0.3초 그대로 있으면 누르고, 안 먹으면 1.5초 뒤 다시 누릅니다 (4번까지).
- 페이지 스크립트를 더 일찍 올리고(`document_end`), 0.2초마다 봅니다 (전엔 0.3초).

0.2.3 (2026-09-19, "쿨다운 없애줘"):

- **쿨다운을 뺐습니다.** 모든 흐름이 새 페이지에서는 기다리지 않고 바로 누릅니다 — 결제 버튼 흐름도 마찬가지입니다.
- 남은 것은 **"한 번 끝낸 흐름은 그 페이지에서 다시 시작하지 않는다"** 하나입니다. 누른 뒤에도 화면에 남는
  버튼(주문서의 결제하기)을 0.2초마다 또 누르지 않게 하려는 것이라 기다리는 시간은 없습니다.
  같은 페이지에서 다시 누르게 하려면 새로고침하면 됩니다.
- 옛 판이 저장해 둔 `cooldownSeconds`·`cooldownScope` 는 알아서 지웁니다.
- 결제가 실패해 주문서가 **새로** 뜨면 결제하기를 다시 누르고, L.PAY 비밀번호도 다시 넣습니다. 틀렸다는 말이
  떠 있으면 비밀번호는 넣지 않지만, 실패가 되풀이되면 흐름을 꺼 주세요.

- 흐름이 몇 번째 단계까지 갔는지는 백그라운드가 쥐고 있어서, 새 창·iframe 으로 넘어가도 이어서 누릅니다.
- 한 번에 한 단계씩, 앞 단계를 누르고 `settleMs`(기본 0.7초) 뒤에 다음을 찾습니다.
- 끝까지 누른 흐름은 그 페이지에서 다시 시작하지 않습니다. 주문서의 결제하기가 한 번만 눌리는 이유입니다.
- 중간에 멈춘 흐름은 2분 뒤 처음으로 돌아갑니다. 바로 돌리려면 설정 화면의 **진행 상태 초기화**.

## 버전 올리기 (깃허브)

버전마다 커밋 하나 + 태그 하나(`v0.3.0` 처럼)를 올리고, 깃허브 릴리스로 남깁니다.

1. `manifest.json` 의 `version` 을 올린다
2. 이 README 에 그 버전에서 바뀐 것을 적는다 (위의 `0.3.0 (…)` 처럼)
3. 커밋·태그·푸시·릴리스:
   ```bash
   git add -A
   git commit -m "v0.3.1: 바뀐 것 한 줄"
   git tag v0.3.1
   git push origin main --tags
   gh release create v0.3.1 --title "v0.3.1" --notes "바뀐 것"
   ```

설치한 쪽은 `git pull` 뒤 `chrome://extensions` 에서 새로고침(↻)하면 됩니다.
